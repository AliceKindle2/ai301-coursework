# Rubric: is this pull request ready to submit?

## Checks

| Check | Evidence | Pass condition | Weight |
|---|---|---|---|
| diff-matches-plan | The branch's diff (`git diff main...HEAD`), read against the plan's stated scope/boundary and its `## Deviations` section | Passes when every changed file falls inside the plan's stated in-scope boundary, or is explicitly accounted for in a recorded deviation note. Fails when the diff touches files or behavior outside both the plan's scope and its deviations, with no note explaining the gap (silent drift, in either direction — doing more than planned, or less with nothing said) | required |
| description-matches-diff | The PR description's claims about what changed, read directly against the diff's actual contents | Passes when every claim the description makes about the change is supported by something actually present in the diff, and the diff contains nothing materially undisclosed. Fails when the description claims more fidelity to the plan than the diff delivers, or omits a change the diff actually makes | required |
| test-evidence-observable | The PR's test-evidence section, read against the plan's test plan and the repo's own CI/check results where visible | Passes when a before/after result is shown with an observable outcome (e.g. "22 passed, 1 xfailed" → "23 passed"), matching what the plan's test plan said to expect, and the repo's own checks (if visible) show passing. Fails when the evidence only asserts "tests pass" with no observable before/after, or the repo's own checks are not run/shown at all | required |
| diff-reviewable | The unified diff and commit list | Passes when every changed hunk is part of the one bounded change the plan describes — no debug leftovers, no commented-out code, no unrelated formatting churn, no drive-by edits to files outside the plan's scope. Fails when the diff requires a reviewer to mentally filter out unrelated noise to find the actual fix | required |
| standards-and-template-followed | The repo-facts block's PR template sections and stated contribution policy (including AI-use disclosure), read against the actual PR description | Passes when every section the repo's PR template asks for contains real, specific content (not boilerplate or an unfilled placeholder), and any required AI-use disclosure is present and specific. Passes by default on the disclosure portion only if the repo states no such policy at all. Fails when a required template section is left blank, templated, or filled with a generic non-answer | required |
| honest-shortfall-disclosed | The PR description's own statements about limitations, deferred edges, or plan deviations | Passes when any genuine shortfall (an edge case not handled, a deviation from the original plan, an honest "could not fully test X") is stated plainly in the description. This check never fails a PR solely for having a limitation — it fails only when a real, discoverable shortfall exists in the diff/evidence but is not mentioned in the description at all | required |

## Verdict rule

The verdict is `accept` when every `required` check grades `pass`, and `reject` when any `required` check grades `fail` or `unclear`. A required check graded `unclear` counts as a fail: the evidence these checks name is present in every package and every real submission, so `unclear` means the signal genuinely could not be found, and a PR whose claims cannot be verified from the package is not ready to submit. There are no `preferred` checks this week; every family named in the evidence guide (plan fidelity, test evidence, diff quality, standards and comms) carries a required check, because the category floor is scored on exactly these names and a missed category cannot be bought back by an unrelated passing check.
